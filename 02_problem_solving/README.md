# 02 — Problem Solving

Practice platforms, one folder per platform:

- `leetcode/`
- `hackerrank/`
- `codewars/`

## Problem Folder Structure

Every problem gets its own folder with three files:

```text
problem-name/
├── solution.py
├── tests.py
└── README.md
```

A ready-to-copy template lives in `_template/`.

## Rules

- Solve the problem yourself before looking at anything.
- Write down your first attempt in the README even if it is wrong — that is the evidence of your thinking.
- Write `tests.py` and run it (`python tests.py`) before considering a solution done.
- Record time and space complexity honestly.
- Record edge cases you missed or handled.
- No copied solutions. If you eventually study a known solution, note it in the README and what you learned from it.
- One problem = one folder. Name folders with the problem name, e.g. `two-sum/`, `valid-parentheses/`.

## Platform Notes

- **LeetCode**: link the problem in the README. While learning, sort by topic, not by difficulty.
- **HackerRank**: note the domain (Python, Algorithms, etc.) in the README.
- **Codewars**: note the kyu level. Start at 8 kyu and go deeper as you improve.
